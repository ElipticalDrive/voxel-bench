# Encyclopedia of rendering schemes

One entry per scheme: every component this project implements, the techniques around them,
every idea for one (built or not), and the ideas behind the bench's own design and tools.
Each entry says what the scheme is, how it works, how it is built here, what has been
measured, and how it relates to the other entries. An entry whose status is `idea` is
untested, and says so at its top.

## An entry

An entry is a Markdown file in the folder of its category, named by its slug
(`storage/prefix.md` is `prefix`). It starts with a TOML header between `+++` lines:

```toml
+++
title = "Morton masks with a popcount prefix"
category = "storage"            # the folder it is in
status = "measured"             # idea | built | measured | rejected
components = ["storage/prefix"] # the registry components that implement it (slot/name)
related = ["hier", "incremental"]   # slugs of other entries
origin = "user"                 # user | project | literature
sources = ["Author, Title, Venue Year"]
+++
```

- `status`: `idea` (untested: not built, or built but not yet tried; the entry starts with
  **Untested idea.**), `built` (works and is tested for correctness, but has not
  been measured), `measured` (numbers in the entry), `rejected` (tried and dropped; the entry
  says why).
- Categories: the folders. Most are kinds of pipeline node; `world` is the server, link and
  client side; `architecture` the bench's design; `tools` the GUI and tooling.
- `origin`: `user` (the project owner's idea), `project` (devised while building this
  bench), `literature` (published or well known; see `sources`).

The body has these sections, in this order: `## What it is`, `## How it works`,
`## In this project` (where the code is, its knobs, how to run it), `## Measured`, and
optionally `## Open questions`. Numbers are from a Ryzen 9 9955HX and an RTX 5060 Laptop GPU
at 1080p unless the entry says otherwise.

## Adding an entry

Write the file, then run `python3 scripts/schemes.py`. It checks every header (fields,
category, status, related slugs) and the sections, and rewrites the index below.
`cargo test` checks that every registry component is named by an entry, so a new component
cannot be added without one.
